# UNA-Watch Simulator on Linux

This guide covers running the GCC-based simulator on Linux x86-64. The official SDK targets Windows + Visual Studio; this page captures everything required to build and run the simulator on Linux.

Tested on: **Ubuntu 24.04 / GCC 13** and **Arch Linux / GCC 15**.

---

## Quick start (using this branch)

This branch (`linux-simulator`) already contains all patches listed below. If you cloned or checked out this branch, jump straight to [Prerequisites](#prerequisites) then [Build](#build).

If you are working from the **upstream `una-sdk` repository**, follow the [Applying patches to upstream](#applying-patches-to-upstream) section first.

---

## Prerequisites

### System packages

```bash
# Debian / Ubuntu
sudo apt install build-essential ruby libsdl2-dev libsdl2-image-dev

# Arch Linux
sudo pacman -S base-devel ruby sdl2 sdl2_image
```

> `ruby` is required by the TouchGFX text and font converter scripts that run during `make assets`.  
> `sdl2_image` is required by the TouchGFX SDL2 HAL for PNG/JPEG loading.

### Ruby gems

The textconvert script requires several gems not bundled with Ruby:

```bash
gem install nokogiri roo rubyXL json erb
```

### Environment variable

The Makefiles require `UNA_SDK` to point to the root of this repository.

```bash
export UNA_SDK=/path/to/una-sdk
```

Add this to your shell profile (`~/.bashrc`, `~/.zshrc`, etc.) to make it permanent.

## Build

### One-time setup: create `config/gcc/app.mk`

`config/gcc/app.mk` is normally generated by TouchGFX Designer (Windows-only tool). On Linux, create it manually inside the app directory. For the HelloWorld example:

```bash
cd $UNA_SDK/Docs/Tutorials/HelloWorld/Software/Apps/TouchGFX-GUI
mkdir -p config/gcc
echo 'touchgfx_path := ../../../../../../ThirdParty/touchgfx' > config/gcc/app.mk
```

The relative path must point to `ThirdParty/touchgfx` from the app directory. The correct value is also listed as `TouchGfxPath` inside the app's `.touchgfx` JSON file.

> This file is gitignored (`/config/gcc/*`) so it will not appear in `git status` and must be re-created after a fresh clone.

### Compile

```bash
cd $UNA_SDK/Docs/Tutorials/HelloWorld/Software/Apps/TouchGFX-GUI
make -f simulator/gcc/Makefile
```

The output binary lands at:

```
build/bin/simulator.out
```

Run it:

```bash
./build/bin/simulator.out
```

### Adding source files

When adding new SDK or app source files to the GCC build, edit the `ADDITIONAL_SOURCES_UNA` or `ADDITIONAL_SOURCES` variables in the app's `simulator/gcc/Makefile` (see `Docs/Simulator.md` § "Include Header & Source file / GCC").

## Applying patches to upstream

If you are starting from the upstream `una-sdk` repository rather than this branch, apply the following changes.

### 1. SDK source patches

Several SDK headers and sources use Windows-only APIs unconditionally. Patch each file as described:

| File | Issue | Fix |
|------|-------|-----|
| `Libs/Header/SDK/Simulator/OS/OS.hpp` | Missing `<array>`, `<condition_variable>`, `<chrono>` includes | Add the three includes at the top |
| `Libs/Header/SDK/Simulator/Kernel/Mock/App.hpp` | Unconditional `#include <windows.h>` | Wrap with `#ifdef _WIN32` / `#endif` |
| `Libs/Header/SDK/Simulator/Kernel/Mock/Logger.hpp` | `GetTickCount64()` is Windows-only | Add `#else` branch using `clock_gettime(CLOCK_MONOTONIC)` |
| `Libs/Header/SDK/Simulator/Kernel/Mock/FileSystem.hpp` | Unconditional `<windows.h>`; `HANDLE`/`WIN32_FIND_DATAA` members | Wrap includes; add `DIR*` / `struct dirent*` Linux members |
| `Libs/Source/Simulator/Kernel/Mock/FileSystem.cpp` | All directory iteration via Win32 (`FindFirstFileA` etc.) | Add POSIX `opendir`/`readdir`/`closedir` path in `#else` blocks |
| `Libs/Header/SDK/Messages/MessageBase.hpp` | `static_assert(sizeof(MessageBase)==32)` — 32-bit ARM layout, fails on x86-64 | Guard with `#if __SIZEOF_POINTER__ == 4` |
| `Libs/Header/SDK/Messages/CommandMessages.hpp` | 18 struct-size `static_assert`s with 32-bit values | Guard each with `#if __SIZEOF_POINTER__ == 4` |
| `Libs/Source/Simulator/Kernel/Mock/System.cpp` | `Sleep(ms)` is Windows-only | Add `#else` branch using `nanosleep()` |
| `Libs/Source/Wrappers/StdLibWrappers.c` | `std::strncpy` in a `.c` translation unit | Change to plain `strncpy` |
| `Libs/Source/Simulator/App/MessageManager.cpp` | Explicit `msg->~MessageBase()` before `delete msg` double-destructs | Remove the explicit destructor call |
| `Libs/Source/Simulator/App/AppCore.cpp` | `handleTickEvent()` called from non-GUI thread on shutdown | Remove the cross-thread calls |

Diff these files against the `linux-simulator` branch in this repo to see the exact changes.

### 2. Ruby tool patches (Ruby 3.2+ compatibility)

The bundled TouchGFX Ruby scripts use APIs removed in Ruby 3.1/3.2. Under `ThirdParty/touchgfx/framework/tools/textconvert/`:

- Replace every `File.exists?` and `File::exists?` with `File.exist?` across `main.rb`, `lib/xml_validator.rb`, and all files in `lib/emitters/`.
- In `lib/emitters/template.rb` and `lib/emitters/fonts_cpp.rb`, change `ERB.new(str, 0, "<>")` to `ERB.new(str, trim_mode: "<>")` (the `safe_level` argument was removed in Ruby 3.1).

### 3. Mark Linux tool binaries executable

The pre-built asset converter binaries ship without the execute bit:

```bash
chmod +x $UNA_SDK/ThirdParty/touchgfx/framework/tools/imageconvert/build/linux/imageconvert.out
chmod +x $UNA_SDK/ThirdParty/touchgfx/framework/tools/fontconvert/build/linux/fontconvert.out
```

> In the `linux-simulator` branch these files are already committed as `0755`, so this step is not needed there.

### 4. App-level patches (per app)

#### Windows.h include guard

App `Model.cpp` files (and other simulator-mode sources) often contain:

```cpp
#if defined(SIMULATOR)
    #include "Windows.h"  // breaks on Linux
#endif
```

Change the guard to:

```cpp
#if defined(SIMULATOR) && defined(_WIN32)
    #include "Windows.h"
#endif
```

The HelloWorld `gui/src/model/Model.cpp` is already patched in this repo.

#### Linker flag (`una/Makefile`)

The pre-built `ThirdParty/touchgfx/lib/linux/libtouchgfx.a` was not compiled with `-fPIE`. Modern GCC enables PIE by default, causing a link failure. Add `-no-pie` to the Linux linker options in each app's `una/Makefile`:

```makefile
linker_options += -static-libgcc -Xlinker --no-as-needed -no-pie
```

The HelloWorld `una/Makefile` is already patched. Apply the same change to any other app you build.

## How the build system works

The GCC Makefile (`simulator/gcc/Makefile`) delegates to `una/Makefile`, which auto-detects the platform via `uname -s`:

- **Linux**: links against `ThirdParty/touchgfx/lib/linux/libtouchgfx.a` plus the system `SDL2`, `SDL2_image`, `jpeg`, `pthread`, `rt`, `dl`, and `m` libraries.
- **Windows (MinGW)**: links against bundled DLLs under `ThirdParty/touchgfx/lib/sdl2/win32/` and `lib/win/mingw32/`.

Pre-built Linux tools (`imageconvert.out`, `fontconvert.out`) live under `ThirdParty/touchgfx/framework/tools/*/build/linux/`.

## Known limitations

- The struct-size `static_assert`s in `MessageBase.hpp` and `CommandMessages.hpp` are **disabled on x86-64**. They encode the 32-bit ARM wire layout; pointer-containing structs will be larger on a 64-bit host. This is fine for simulation but means the simulator and firmware use different in-memory layouts.
- Each app's `una/Makefile` needs the `-no-pie` flag added manually. The HelloWorld example is patched; other tutorial apps are not.
- Each app needs a `config/gcc/app.mk` created manually on Linux (TouchGFX Designer normally generates this on Windows). See [One-time setup](#one-time-setup-create-configgccappmk) above.
- The official team supports Windows only. Linux support is community-maintained.
